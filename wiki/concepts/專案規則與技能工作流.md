# 專案規則與技能工作流

在現代 AI 程式代理（如 [[Claude Code]]）的架構中，將指導方針劃分為「靜態專案脈絡」（以 `CLAUDE.md` 或 `AGENTS.md` 為代表）與「動態操作規程」（以 `SKILL.md` 為代表）的雙層分工模式。

## 定義
- **靜態專案規則（`CLAUDE.md` / `AGENTS.md`）**：定義專案全域、長期的架構邊界、命名慣例、依賴版本限制及不可變規則。當 Agent 讀取專案背景時載入 ([[mattpocock-skills-repo]])。
- **動態操作規程（`SKILL.md`）**：定義在特定開發工作（如需求分析、[[TDD]]、除錯、Code Review）中的標準作業步驟、推論鏈與品質檢查清單。依據呼叫或觸發條件動態載入 ([[mattpocock-skills-repo]])。

## 兩者的對比與互補

| 維度 | 專案規則檔（`CLAUDE.md`） | 技能指引檔（`SKILL.md`） |
| --- | --- | --- |
| **主要用途** | 專案的長期約束與背景 | 特定工作的操作流程與手續 |
| **核心內容** | 架構邊界、命名規則、技術棧約束 | 規劃、測試、除錯、重構步驟 |
| **載入時機** | Agent 啟動或讀取專案指引時 | 依照呼叫方式或工作階段動態觸發 |
| **複用性** | 專案特定（Project-specific） | 跨專案通用（Cross-project reusable） |

兩者為**完全互補**而非二選一。例如在專案規則中規定「必須支援特定版本技術棧且維持既有架構」，再搭配通用 `tdd` Skill（參見 [[TDD]]）強制紅綠燈循環實作 ([[mattpocock-skills-repo]])。
